# GOLDENPATH.md

## End State

The parent wrapper can initialize, observe, evaluate, and challenge any child
wrapper using:

- the same fractal scaffold
- the same governed prompt contract
- the same InfraNodus phase map
- the same Pixeltable substrate doctrine
- the same seven-gate lifecycle

## Path

1. Parent wrapper identifies the active body cell.
2. Parent wrapper finds the child `meta/` surface for that body cell.
3. Child wrapper exposes `README.md`, `AGENTS.md`, `CLAUDE.md`, `MEMORY.md`,
   `GOAL.md`, and `GOLDENPATH.md`.
4. Parent wrapper loads `library.yaml`, `program.md`, the prompt-contract set,
   the imported local upstream authorities, the InfraNodus phase-tool map, and
   the substrate doctrine.
5. Child wrapper emits durable gate-state, proof, and score artifacts.
6. Parent wrapper uses InfraNodus across the active gate to identify gaps,
   drift, and unsupported claims.
7. Parent wrapper records those artifacts and chooses the active optimization
   gate.
8. Earlier gates remain regression gates while the active gate is optimized.
9. The same parent-child pattern can be reused for the next project body.

## Guardrails

- No wrapper level is complete without the six-file minimum scaffold.
- No heavy prompt is valid without the governed prompt contract.
- No gate claim is green without durable artifacts.
- No gap pass is complete without InfraNodus evidence.
- No durable state is complete without a Pixeltable-oriented substrate path.
