# Agentics Library

This parent wrapper incorporates the library pattern as the catalog spine for:

- prompts
- capabilities
- references
- reusable wrapper contract surfaces
- imported upstream authority surfaces
- bounded parent tool-health evidence
- harness-improvement evaluation lanes

The durable asset is the entry in `library.yaml`. The working copy is
replaceable. The parent wrapper carries the authoritative catalog so any child
repo can mirror it without redefining the library spine. The imported local
clones under `external/` are part of that spine, not optional footnotes.

Current improvement-layer capabilities include GitNexus and Graphify for
bounded parent graph analysis, InfraNodus for doctrine-backed gap analysis,
CLI-first local runner harvests for baseline execution truth, a reusable parent
metrics contract for capability harvests and improvement lanes, and Vercel
agent-eval as a parent-scoped exception lane with a kept dry fixture today and
remote-provider smoke or live only when that exact prerequisite is truly
configured.

The parent wrapper now also carries first-class orchestration surfaces for the
Pi-to-Pi peer mesh, peer message envelopes, peer lifecycle transitions,
observability events, policy decisions, peer mesh runtime modes, governed agent
roles, fail-loud hook policy, and a bounded capability matrix that places the
upstream Disler capability set into explicit parent contracts. The Phase 1 kept
slice makes prompt and command guarding explicit, binds same-host plus
cross-device runtime modes to role classes, and records correlation plus
completion boundaries directly in the communication contracts.

The Phase 2 kept slice adds a decoupled observability ingest plane, a
the-library-style typed distribution contract, and benchmark-emission surfaces
so peer-mesh regression evidence is governed and portable instead of implied by
logs or prose.

The next governance slice makes the three-agent control core explicit above the
runtime mesh. `contracts/three-agent-topology.yaml` now defines the
`orchestrator-validator`, `research`, and `architect` roles as parent-only
governance profiles, while `contracts/agent-extension-request.yaml` gives that
same triad a bounded way to propose new parent-native agent or prompt surfaces
without claiming runtime auto-provisioning exists.

This triad slice also adds a dual-artifact handoff rule. Structured YAML/JSON
artifacts remain machine truth, while
`prompts/governed-triad-follow-up-prompt.template.md` provides the companion
Markdown surface for operator-facing routing, front matter, bottom matter, and
dispatch clarity.

The next parent-native layer is the governed inbox front door. The packet
itself is a Markdown transport document with YAML front matter and bottom
matter, but routing truth stays in `contracts/inbox-routing-decision.yaml`,
runtime handoff truth stays in `contracts/delegation-bundle.yaml`, and the
bridge between governance review and runtime execution stays explicit in
`contracts/front-door-runtime-topology.yaml`. That keeps the triad as a control
plane instead of quietly turning it into the runtime mesh.

The compiled research harvest under `evaluation/research/` is now governed as a
first-class parent surface through `contracts/research-packet-manifest.yaml`,
schema-backed compiled output validation, and a capability matrix that stays
aligned with the compiled feature matrix, source refs, lane classifications, and
video-evidence truth boundaries.

The first real runtime lane is now a bounded same-host slice under
`scripts/run-parent-peer-mesh-local.sh`. It resolves typed prompt, skill,
agent, policy, validator, and benchmark-recipe refs from `library.yaml`, emits
governed peer-mesh observability into `evaluation/tool-health/`, and keeps
cross-device, provider-backed, sandbox, and browser follow-ons explicitly
blocked or gated instead of implying they came alive with the same-host lane.
