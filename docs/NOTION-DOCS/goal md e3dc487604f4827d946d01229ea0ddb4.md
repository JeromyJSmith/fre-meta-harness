# goal.md

## Goal (v1)

<aside>
📎

**Purpose**: Defines measurable success criteria (“done means”) and the keep/revert rule for the meta-harness.

**Inputs**: Golden path outputs; validation results; run logs and scores.

**Outputs**: Acceptance criteria + metrics used by the evaluation gate.

**Validation tie-in**: Publish decision (keep/revert), Drift detection (regressions), Golden tests (green definition).

**Failure modes**: Without measurable criteria, improvements can’t be judged and drift becomes opinion.

**Update / upstream path**: Metric/criteria changes require schema + example updates and must be recorded in run logs.

</aside>

```yaml
page_contract:
  purpose: "Acceptance criteria + metrics for the portable harness."
  inputs: ["Golden path results", "Run logs", "Compiler outputs"]
  outputs: ["Measurable acceptance criteria", "Keep/revert rule"]
  validation_tie_in:
    gates: ["Publish decision", "Drift detection"]
    checks:
      - "Criteria are measurable and referenced by validation outputs"
  failure_modes:
    - "No objective 'green'"
    - "Changes kept without evidence"
  upstream:
    update_artifact: "Goal/metrics update artifact"
    proposal_path: "Patch goal + rerun evaluation + record decision"
```

Define what “better” means.

### Primary metric

- `goal_pass_rate`

### Secondary metrics

- `time_to_green`
- `manual_interventions`
- `spec_compliance`

### Keep / revert rule

- Keep changes only if primary metric does not regress.

### Acceptance criteria (measurable)

- Golden path runs to green on a fresh export.
- Compiler outputs `compliance.md` + `missing.md`.
