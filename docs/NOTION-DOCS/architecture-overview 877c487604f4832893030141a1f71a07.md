# Architecture Overview

META-HARNESS treats architecture work as a coordinated system of research, specification, agent execution, and validation.

## Artifact layers

- RDD layer: defines why the system exists, what constraints matter, and which acceptance criteria govern implementation.
- Research layer: captures evidence, source synthesis, experiments, and unresolved uncertainty.
- Specification layer: turns evidence into implementation commitments.
- Agent layer: defines which autonomous or semi-autonomous roles may read, write, validate, or hand off artifacts.
- Validation layer: records checks, evidence, pass/fail gates, and promotion recommendations.
- Canonical layer: identifies the current authoritative artifacts and supersession lineage.

## Spatial transformation path

The default domain path is:

```
Vectorworks source model
  -> exchange extraction
  -> semantic and geometric normalization
  -> mapping specification
  -> iTwin ingestion package
  -> validation evidence
  -> canonical architecture record
```

## Required traceability

Every implementation-facing output should be traceable back to:

- An RDD requirement.
- A research or decision artifact.
- A validation gate.
- A current or proposed canonical spec.
