# README

# META-HARNESS Architectural Specification Repository Template

This repository is a living-document template for META-HARNESS architectural specifications, research-driven development artifacts, agent role contracts, validation records, and canonical implementation guidance.

It is designed for Vectorworks-to-iTwin spatial data systems where design-authoring geometry, BIM metadata, GIS context, and downstream digital twin representations must remain traceable from requirements through implementation.

## Repository layout

```
.
├── agents/                 # Agent role contracts and executable handoff definitions
├── diagrams/               # Mermaid diagrams for lifecycle, pipeline, and architecture views
├── docs/                   # Governance, conventions, and operating model
├── examples/               # Complete example artifacts for reference
├── rdd/                    # Research-driven development input documents
├── research/               # Research notes, source syntheses, experiment reports
├── schemas/                # JSON Schema definitions for manifests and contracts
├── specs/                  # Architecture, interface, data, and implementation specs
├── templates/              # Reusable living-document templates
├── tools/                  # Validation and promotion automation hooks
└── validations/            # Validation plans, test evidence, acceptance records
```

## Living-document lifecycle

Artifacts move through four canonical states:

- `Draft`: exploratory, incomplete, or author-local.
- `Research`: supported by source material, experiments, or RDD traceability.
- `Validated`: checked against schemas, acceptance criteria, regression tests, and reviewer gates.
- `Canonical`: approved as the current implementation reference.

The promotion model is defined in .

## META-HARNESS alignment

The template assumes a META-HARNESS workflow where:

- Research-driven development documents establish intent, constraints, and acceptance criteria.
- Specs translate research into executable architectural commitments.
- Agents operate under explicit role contracts with scoped permissions and handoff obligations.
- Validations bind evidence back to requirements, transformations, and implementation outputs.
- Canonical documents remain supersedable rather than static.

## Vectorworks-to-iTwin focus

Spatial data artifacts should preserve lineage across:

- Vectorworks project source files and exported geometry.
- IFC, glTF, 3D Tiles, GeoJSON, and intermediate exchange formats.
- Coordinate reference systems, georeferencing transforms, and unit normalization.
- iTwin schemas, element mappings, categories, models, aspects, and metadata bindings.
- Validation evidence for geometry fidelity, semantic completeness, and round-trip drift.

## Quick start

1. Copy this template into a new repository.
2. Add RDD inputs under `rdd/`.
3. Create research artifacts under `research/` using `templates/research-note.md`.
4. Define specs under `specs/` using `templates/spec.md`.
5. Define agent role contracts under `agents/` using `schemas/agent-role-contract.schema.json`.
6. Record validations under `validations/` using `templates/validation-record.md`.
7. Promote artifacts by updating front matter and bottom matter according to `schemas/living-document-manifest.schema.json`.

## Validation

Schema validation is intentionally tool-agnostic. A lightweight Python validator is included at `tools/validate_schemas.py` for checking the repository schemas and example JSON/YAML contract files.
