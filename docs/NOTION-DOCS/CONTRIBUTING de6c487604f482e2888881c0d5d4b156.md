# Contributing

This repository is governed as a living-document system. Contributions should improve traceability, validation quality, or implementation readiness.

## Contribution types

- RDD updates that clarify requirements, constraints, or acceptance criteria.
- Research notes that add evidence, experiment results, or prior-art synthesis.
- Specs that translate RDD and research inputs into architectural commitments.
- Agent contracts that define bounded automation roles and handoff behavior.
- Validation records that attach evidence and promotion recommendations.

## Pull request expectations

- Update the artifact manifest when changing lifecycle state, ownership, provenance, RDD links, or validation evidence.
- Add or update validation records for implementation-impacting changes.
- Do not promote documents to `Canonical` without reviewer approval and registry updates.
- Preserve supersession lineage when replacing a canonical artifact.

## Naming conventions

- Use lowercase kebab-case file names.
- Prefix RDD files with the domain or workflow they govern.
- Name agent contracts as `role-name.contract.json`.
- Name validation records as `artifact-name-validation.md`.
